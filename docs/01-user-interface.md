# LILYGO UI NES 开发规范

本文规定本项目的 UI 架构、视觉、交互和验收要求。新增或修改页面、组件、布局、
样式、文案或字体时必须遵守本文。

项目介绍与构建步骤见 [中文 README](../README.zh-CN.md) 或
[English README](../README.md)，线程和模块说明见 [架构总览](00-overview.md)，
用户操作和环境变量见 [ROM 与运行配置](02-roms-and-runtime.md)。

本文中“必须”和“不得”是强制要求，“应”是默认实现方式。开始编辑前，
必须先检查当前页面、`src/components/` 中的现有能力和相关测试，不得假设
仓库中存在未实现的基类、主题或响应式辅助 API。

## 架构边界

| 关注点 | 位置 | 规则 |
| --- | --- | --- |
| 页面状态和 UI | `src/pages/library/`、`rom_browser/`、`game/`、`settings/`、`help/` | 每个页面拥有独立 ViewModel 和 View；ViewModel 管理展示状态与命令，View 创建本页控件并转发事件。 |
| 页面组合与导航 | `src/pages/nes/` | `NesViewModel` 组合各页面 ViewModel；`NesView` 组合各页面 View，管理导航、共享错误弹窗、keypad 订阅和轮询定时器。 |
| ROM 领域规则 | `src/domain/rom_library.*` | 扫描、浏览、导入、解析、排序和删除 ROM，不得依赖 LVGL。 |
| 模拟器适配 | `src/emulator/nes_emulator.*` | 管理模拟器、按键状态、帧交付和音频；后台线程不得操作 LVGL。 |
| 平台输入 | `src/platform/multitouch_reader.*` | 读取触点并发布快照；控件命中判断由 View 在主线程完成。 |
| 通用组件 | `src/components/` | 复用现有组件和语义样式，明确所有权和销毁顺序。 |
| 应用生命周期 | `src/app.cpp` | 创建 `NesViewModel` 与 `NesView` 容器，先销毁全部页面 View 和容器，再销毁 ViewModel。 |

依赖方向必须是：

```text
页面 View -> 对应页面 ViewModel -> RomLibrary / NesEmulator / 按键映射
NesView 组合页面 View；NesViewModel 组合页面 ViewModel
```

- Model 保存业务状态和领域规则，必须能在不初始化 LVGL 的情况下测试。
- ViewModel 将 Model 转换为展示状态并提供用户命令，状态在命令完成或定时轮询后同步到 View。
- View 只负责 LVGL 对象创建、布局、事件转发和状态绑定，不得直接修改 Model。
- 页面之间通过 `NesPageCallbacks` 请求导航和状态同步，不得直接操作其他页面的 LVGL 对象。
  `NesView` 的定时器调用 `GameView::tick()` 和 `NesViewModel::poll()`；游戏触摸、帧资源和控件
  由 `GameView` 管理，设置页的捕获状态与保存反馈由 `SettingsViewModel` 管理。
- 全部 ViewModel 编译到 `lilygo_ui_nes_view_models`，只链接 `lilygo_ui_nes_core`，不得链接 LVGL。
  `lilygo_ui_nes_ui` 链接 ViewModel target；`nes-view-model-tests` 只链接 ViewModel target。

数据流必须保持单向：

```text
用户输入 -> View 回调 -> ViewModel 命令 -> 核心状态更新
         -> 状态读取 -> View 更新 -> LVGL 渲染
```

## 字体与文本

- 显示文本的 UI 源文件必须包含 `<cm0/typography.h>`。除下述应用专用字体场景外，
  LVGL 文本对象必须使用 `lilygo_ui_font_get(size)` 返回的 AppKit 字体。
- 必须在 `lv_init()` 完成后获取字体。`14`、`22`、`28`、`36` 和 `48` 像素是
  推荐的基础字号；产品层级或布局确有需要时，可向 `lilygo_ui_font_get(size)`
  传入其他正整数字号。
- AppKit 在首次请求某个字号时创建并缓存对应的完整字体链，后续相同字号复用该
  缓存。不得根据视口尺寸连续计算字号，也不得为相近文本层级引入大量不同字号；
  每个不同字号都会占用额外字体缓存，直至字体系统反初始化。
- 设置文本样式前必须确认字体指针非空。返回的字体对象及其 fallback 链由 AppKit
  共享和管理，应用不得修改或释放。
- 相同信息层级在同一应用中应使用一致的字号。缩小字号不得作为修复溢出的
  首选方案；应先精简文案、调整布局，或按产品要求换行和截断。
- 不得在公共 UI 中引用 `lv_font_montserrat_*`，也不得复制、改名或随应用重新打包
  AppKit 字体。

AppKit 在运行时通过 LVGL FreeType 加载共享字体文件。`lilygo_ui_font_get()` 返回
以 Inter 为主字体、Source Han Sans CN 为中文 fallback、Font Awesome 为图标字形
fallback 的字体链。中西文混排必须使用同一个字体链，不得为了切换字体拆分标签，
也不得依赖操作系统字体发现或默认字体回退。

### 应用专用字体

仅当 AppKit 运行时字体确实缺少应用所需字形时，才可在 `assets/fonts/` 提供
应用专用的 TTF、OTF 或 WOFF 字体。不得复制或重新打包 AppKit 已提供的 Inter、
Source Han Sans CN 或 Font Awesome 字体。应用专用字体必须满足：

- 通过 `lv_freetype_font_create()` 按当前 UI 字号在运行时加载；
- 将应用专用字体作为引用它的 LVGL 对象的主字体，并将其 `fallback` 设为同字号的
  `lilygo_ui_font_get(size)` 结果；
- 不得修改 `lilygo_ui_font_get()` 返回的共享字体对象或它的 fallback 链；
- 字体对象的生命周期必须不短于引用它的 LVGL 对象；移除所有引用后，必须通过
  `lv_freetype_font_delete()` 释放；
- 字体文件必须通过应用的安装和打包规则部署到稳定的运行时路径；
- 可通过可重复的子集化流程仅保留所需字形以减小安装体积，但不得手工修改生成的
  字体文件。

AppKit 的 Inter、Source Han Sans CN 和 Font Awesome 字体按 SIL Open Font License 1.1
分发。应用不得将它们描述为“无版权字体”或单独销售。包含字体的分发物必须
保留 `NOTICE.md` 和 `OFL-1.1.txt`；项目通过 AppKit 安装辅助函数包含共享字体的
许可文件。新增应用专用字体时，必须同时记录字体来源，并补充该字体的许可文件
和打包规则。

## 响应式布局

- 页面主体必须使用 LVGL Flex 或 Grid，并结合百分比尺寸、`LV_SIZE_CONTENT`、
  最小/最大尺寸、对齐、间距和滚动容器分配空间。
- 不得用大量绝对坐标组织页面主体，不得为横屏、竖屏或不同尺寸复制整套
  页面。
- 固定像素值只能用于有明确约束的尺寸，例如图标、边框、间距、控件下限和设计
  token。
- 连续尺寸变化应由 layout 自动处理。只有导航方向、栏数、内容优先级或交互
  方式发生结构变化时才设置断点。
- 断点必须依据父容器的实际可用宽高，不得依据 CPU 架构、设备型号或应用展示
  模式。可复用组件不得假设自己占满 display。
- 尺寸变化的布局更新必须可重复执行，不得把重建整个页面作为常规适配方式，
  并必须保留业务状态、焦点、滚动位置和用户输入。

响应式结果必须保证：

- 文本按产品要求换行或截断，不与相邻内容重叠；
- 主要操作始终可见、可达，并有足够的命中区域；
- 内容增多、文案变长或字体回退时，容器可扩展、重排或滚动；
- 横竖屏和尺寸切换后业务状态和用户输入不丢失。

### NES 页面布局

标准验收视口为竖屏 `568 x 1232` 和横屏 `1232 x 568`。当前页面在可用宽度至少
800 像素且大于主体高度时采用横屏结构；新断点必须继续依据实际容器尺寸。

- 页面不显示独立的 NES 标题栏，游戏面板使用页面的全部可用高度；运行时不显示 `Running <title>` 状态行。
- 主页面不显示 `status_` 信息。错误使用居中警告弹窗，白色圆角容器配黑色、40% 不透明度遮罩。
- ROM 库采用 Flex 纵向布局：横竖屏均为全宽单列列表，Add ROM 位于列表最后一项并随列表滚动，
  列表下方固定工具栏依次提供刷新、设置和帮助。滚动列表时工具栏保持可见，列表不得被工具栏遮挡；不得新增摘要面板、
  ROM 数量显示或为展示数量而统计目录。长游戏名完整换行，条目高度随文本增长；元数据允许按现有规则省略。
- 无 ROM 时列表中仅保留 Add ROM，不显示空库说明卡片或 `Ready to play` 状态。
  刷新、设置和帮助按钮为 `77 x 77` 像素，间距为 `16` 像素，分别按原尺寸和间距的约 `1.6` 倍放大。
- 帮助使用独立页面和可滚动内容区，显示由当前用户 `$HOME` 展开的完整 `nes/rom` 和 `nes/states` 目录路径，
  长路径可换行且全部可读。帮助页和设置页提供 Back 返回游戏库，横竖屏均保持导航可达。
- 游戏页采用 Grid：竖屏画面、方向键和 A/B 自上而下排列；横屏方向键、画面和 A/B 分列左右。
  A/B 沿 45° 对角线排列，A 在右上、B 在左下，触摸区域保持间隔。
  Save、Load、Select、Start 和停止按钮位于同一控制行。
- 游戏页顶部状态条显示保存、读取过程及操作结果；横竖屏下均保持可见，
  不得遮挡画面或其他游戏控件。
- `256 x 240` 的 RGB565 帧必须等比缩放，游戏控件不得遮挡画面。
- 标准验收视口的游戏按钮尺寸和间距按原布局约 `1.6` 倍放大；方向按钮保持正方形，
  A/B 保持圆形且间距至少 50 像素，方向键网格间距为 10 像素。较小视口可根据可用空间
  回退放大比例。按下和释放不得改变布局尺寸。
  放大后所有按钮及其文字仍须完整可见，按钮之间不得重叠，Select、Start 和停止按钮
  所在容器必须独立保留足够宽度，不得因画面等比缩小而裁切。
- 调整尺寸必须复用现有 LVGL 对象，更新触摸坐标映射，保留正在运行的游戏。

## NES 交互规则

- ROM 列表最后一项 **Add ROM** 打开应用内文件选择器，从用户主目录开始，只展示目录和 `.nes` 文件，提供根目录、
  上一级和取消操作。目录和长文件名必须可读，横竖屏下均可浏览和选择。
- 选择 `.nes` 文件后校验 iNES 头，复制到 `$HOME/nes/rom` 并保留源文件，目标目录按需创建。
  同名文件不得覆盖；成功后关闭选择器并刷新列表，失败则留在选择器并显示原因。
  `$HOME/nes/rom` 已有 128 个 `.nes` 文件时拒绝导入，并显示游戏库已满。
  运行或停止游戏期间不得导入 ROM。
- 点击 ROM 卡片的标题、图标或元数据均可启动游戏；拖动不得误触启动。
- 向左滑动卡片显示删除按钮，向右滑动收起；纵向滑动只滚动列表。
  从删除按钮区域发起的纵向滑动也不得删除文件。
- 删除是直接移除磁盘 ROM 文件的操作，点击删除后立即执行，没有确认对话框。成功后刷新列表，失败时保留条目并显示错误；
  不得让界面看起来已经成功删除。对应的 `.state` 和 `.sav` 文件保留。运行或停止游戏期间不得删除 ROM。
- 刷新在 ROM 列表下方的固定工具栏中提供，新增或移除外部 ROM 后由用户主动刷新。
  启动和刷新游戏库时创建缺失的 `$HOME/nes/rom` 目录。
- 帮助按钮打开独立帮助页，说明实际 ROM 和存档目录、导入 `.nes`、手动复制后刷新、点击启动、
  左滑直接删除磁盘文件、按键映射、Save / Load 以及方向键、A/B、Select、Start 和 Stop 等游戏控制。
- 游戏按键使用按下、释放与失去按压事件，必须支持方向与 A/B 同时按住。
  合并 LVGL 和直接触摸输入时，不得因其中一个来源释放而清除另一来源仍按住的按钮。
- 游戏运行时从 AppKit 的 keypad 输入接收 P1 键盘映射：W/S/A/D 控制方向，K/J 控制 A/B，I/U
  按帧交替触发 A/B 连发，1/2 控制 Start/Select。离开游戏、输入设备重连或页面销毁时必须清理键盘
  及连发状态；P2 输入不参与映射。
- ROM 库设置页的每个 P1 动作行都可点击编辑；点击后捕获下一次键盘按下并立即保存。新键已被其他
  动作占用时拒绝修改并提示用户重新选择；映射文件位于 `$XDG_CONFIG_HOME/lilygo-ui-nes/keymap.conf`
  或 `$HOME/.config/lilygo-ui-nes/keymap.conf`。
  映射条目高度、表头高度、行间距及垂直内边距按原尺寸放大约 1.6 倍；列表可滚动，最后一项必须可达。
- 停止按钮请求模拟器正常退出；界面在收到结束通知后回到 ROM 库。
  离开游戏和销毁页面时必须清除所有按键状态。
- Save 为当前 ROM 保存一份即时存档，重复保存覆盖上一份；Load 恢复该 ROM 上一次保存的状态。
  命令异步交给模拟线程，处理中 Save / Load 同时禁用；完成后更新工具栏结果并恢复按钮。
  无存档、文件损坏、ROM 不匹配或文件系统错误需显示具体原因，普通存档失败不退出游戏。
  存档位于 `$HOME/nes/states/<完整ROM文件名>.state`；电池 RAM 使用同目录下的
  `<完整ROM文件名>.sav`，继续在启动时读取、正常停止时写出。
- `Error` 出现时立即弹窗显示具体原因，5 秒后自动关闭；弹窗期间阻止操作底层页面。
  无效 ROM、导入失败、启动失败和文件删除失败应可区分，长错误信息应换行且可滚动阅读。
  页面刷新或返回不得重复弹出旧错误；再次操作产生相同错误时必须重新提示。

## LVGL 对象和生命周期

- View 必须在调用者传入的 `parent` 下创建顶层对象，不得假设 parent 是当前
  screen 或整个 display。
- 页面 View 必须保存自己的顶层 LVGL 对象，重复创建时返回已有对象，并提供可重复调用的销毁流程。
- LVGL 父对象负责删除子对象。销毁父对象后必须清空所有缓存的子对象指针，
  不得重复删除。
- 事件回调使用 `user_data` 时，其指向对象的生命周期必须覆盖事件注册期间。
- 优先使用 LVGL 对象绑定的 observer。全局 observer、输入监听器、timer 和其他非对象
  绑定资源必须在销毁时显式注销。
- ViewModel 必须比读取其状态和调用其命令的 View 存活更久。
- 延迟页面切换时，不得在当前 LVGL observer 或事件回调中同步删除触发回调的
  页面。
- 需要被渲染测试定位的关键对象必须设置稳定、有语义的 `lv_obj_set_name_static()`
  名称。

应用容器的清理顺序为：删除轮询和错误弹窗定时器、注销 keypad 监听，再由 `GameView`
停止触摸线程、请求模拟器停止、释放按键。各页面分别删除自己的 LVGL 根对象并清空缓存指针，
最后删除容器根对象；全部 View 销毁后才销毁 ViewModel，并由 `GameViewModel` 中模拟器的
析构等待线程退出。不得在重排布局时重启工作线程。

## 新增页面

新增页面前必须先检查 `src/pages/` 和现有测试。现有 ROM 库、文件选择器、游戏、设置和帮助
各自使用独立目录中的 ViewModel 与 View，`src/pages/nes/` 仅承担应用页面组合和协调。
不得将新页面的控件和命令并入其他页面，也不得仅为目录形式一致而迁移现有 `RomLibrary`
或引入未使用的路由。新增页面时通常包含：

1. 按需新增 `src/pages/<page>/<page>_model.cpp/.hpp`：页面私有状态和领域规则；已有领域 Model 应复用；
2. `src/pages/<page>/<page>_view_model.cpp/.hpp`：命令和展示状态；
3. `src/pages/<page>/<page>_view.cpp/.hpp`：LVGL 对象、绑定、回调和响应式布局；
4. `src/pages/nes/` 容器中的组合、导航和销毁；应用级生命周期继续由 `src/app.cpp` 管理；
5. Model、ViewModel 和用户可见行为的测试；
6. 更新用户文档，并生成、检查相关渲染预览；测试产物无需加入源码仓库。

页面私有 Model 与 ViewModel/View 放在同一目录，但仍必须编译到不同依赖层。纯 Model
和 ViewModel 代码不得因为目录内聚而链接 LVGL。

## 新增通用组件

只有组件被多个页面使用，或它明确承担通用绑定、样式或资源生命周期时，才放入
`src/components/`。否则应保持在所属页面目录。

通用组件必须：

- 在调用者传入的 parent 下构建；
- 以父容器的可用尺寸进行响应式布局；
- 复用语义颜色和 AppKit 字体；
- 声明所有权、回调 `user_data`、observer、timer 和销毁责任；
- 在最长文案、字体回退和支持视口下不发生重叠、裁切或不可达操作。

## 验收

每次 UI 修改必须在仓库根目录至少完成：

```sh
cmake --preset host-simulator
cmake --build --preset host-simulator --parallel
ctest --preset host-simulator
```

也可使用 `lpm test` 执行上述流程。现有测试包括：

| 测试 | 覆盖内容 |
| --- | --- |
| `nes-core` | 不初始化 LVGL 的 ROM 扫描、目录浏览、导入校验与冲突、iNES 元数据和文件删除。 |
| `nes-audio` | SDL2 采样数、资源生命周期、音频失败恢复和 PCM 文件输出。 |
| `nes-view-model` | 空库、无效 ROM、展示状态、导入与删除错误和运行时文件操作保护。 |
| `nes-render-portrait` | `568 x 1232` 竖屏 ROM 库、游戏运行和主要交互。 |
| `nes-render-landscape` | `1232 x 568` 横屏 ROM 库、游戏运行和主要交互。 |

两个渲染测试自行生成最小 NROM，覆盖无标题栏的游戏布局、全宽单列游戏库、固定工具栏、
帮助页的实际目录和长路径换行、帮助内容独立滚动与 Back、设置页、空库、文件浏览与导入、卡片不同区域的点击、长标题、放大按键的命中区域与间距、横竖屏切换后的按键和画面
无重叠及文字无裁切、组合按键、停止返回、滑动删除、纵向滚动和删除失败后的
状态、错误弹窗的自动关闭和重复操作提示。每个视口输出九个阶段的图像：

| 阶段 | `build/host-simulator/` 中的输出 |
| --- | --- |
| 游戏运行 | `nes-portrait.ppm`、`nes-landscape.ppm` |
| ROM 库 | `nes-portrait-library.ppm`、`nes-landscape-library.ppm` |
| ROM 列表末尾（Add ROM） | `nes-portrait-library-end.ppm`、`nes-landscape-library-end.ppm` |
| ROM 文件选择器 | `nes-portrait-browser.ppm`、`nes-landscape-browser.ppm` |
| 删除按钮展开 | `nes-portrait-delete.ppm`、`nes-landscape-delete.ppm` |
| 帮助页 | `nes-portrait-help.ppm`、`nes-landscape-help.ppm` |
| 按键映射设置 | `nes-portrait-settings.ppm`、`nes-landscape-settings.ppm` |
| 错误弹窗 | `nes-portrait-error.ppm`、`nes-landscape-error.ppm` |
| 空游戏库 | `nes-portrait-empty.ppm`、`nes-landscape-empty.ppm` |

测试通过不能替代视觉检查。修改 UI 时还必须检查这十八张渲染产物，并确认：

- 布局不依赖单一固定分辨率；
- 文本无缺字、错误回退、重叠或裁切；
- 主要操作可见、可达，按钮文案和命中区域正常；
- 尺寸或方向变化后布局正确重排，业务状态、焦点、滚动位置和用户输入保留；
- 页面背景、容器、文本、边框和主操作使用正确的语义颜色；
- 关闭页面后无野指针、重复删除、未注销 observer、timer 或输入监听器。

模拟器测试不验证真实 evdev 多指输入或 ALSA 输出。修改触控、方向适配或设备音频时，
还必须在设备上验证方向与 A/B 同时按下、手指移出和释放、停止游戏后的按键清理及声音输出。

修改 SDK、工具链、安装或打包相关 UI 资源时，还必须完成 `cm0-cross` 构建和
Debian 打包验证。
